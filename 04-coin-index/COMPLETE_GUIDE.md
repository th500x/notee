## 项目概述

### 🎯 项目定位
区块指标是一个专业的区块链市场指标分析工具，通过12个核心指标的综合分析，为投资者提供量化的市场评级和投资建议。

### 🏗️ 技术栈
- **前端**: React + Vite + Tailwind CSS
- **数据源**: CoinGecko API (价格数据) + Yahoo Finance API (历史数据) + 手动CSV导入 (技术指标)
- **数据格式**: JSON
- **脚本语言**: Node.js

### 📁 项目结构

## 核心指标说明

### 📊 12个核心指标

#### 1. BTC周涨跌幅
- **计算方式**: (本周BTC均价 - 上周BTC均价) / 上周BTC均价 × 100%
- **数据来源**: CoinGecko API / Yahoo Finance API
- **特殊处理**: 2025-W01使用首尾价格计算（无上周数据）

#### 2. BTC距ATH回撤
- **计算方式**: (当前价格 - ATH价格) / ATH价格 × 100%
- **ATH标准值**: 分阶段设置（见评分系统章节）
- **数据来源**: 自动计算

#### 3. BTC周均价
- **计算方式**: 周内7天价格平均值
- **数据来源**: CoinGecko API / Yahoo Finance API
- **单位**: USD

#### 4. ETH周均价
- **计算方式**: 周内7天价格平均值
- **数据来源**: CoinGecko API / Yahoo Finance API
- **单位**: USD

#### 5. ETH/BTC市值比
- **计算方式**: ETH价格 / BTC价格
- **数据来源**: 自动计算
- **用途**: 衡量ETH相对BTC的强弱

#### 6. 恐惧&贪婪指数
- **范围**: 0-100
- **数据来源**: 手动CSV导入
- **含义**: 
  - 0-20: 极度恐惧
  - 20-40: 恐惧
  - 40-60: 中性
  - 60-80: 贪婪
  - 80-100: 极度贪婪

#### 7. 梅耶倍数 (Mayer Multiple)
- **计算方式**: 当前价格 / 200日移动平均线
- **数据来源**: 手动CSV导入
- **含义**: 
  - <0.8: 严重低估
  - 0.8-0.9: 低估
  - 0.9-1.1: 合理
  - 1.1-1.2: 轻微高估
  - >1.2: 高估

#### 8. Ahr999指标
- **计算方式**: 综合性抄底指标
- **数据来源**: 手动CSV导入
- **含义**:
  - <0.4: 抄底区间
  - 0.4-0.8: 定投区间
  - 0.8-1.2: 观望区间
  - 1.2-1.6: 谨慎区间
  - >1.6: 高风险区间

#### 9. BTC四年指数
- **计算方式**: 基于四年周期的估值指标
- **数据来源**: 手动CSV导入
- **含义**:
  - <1.6: 极度低估
  - 1.6-1.8: 低估
  - 1.8-2.0: 合理
  - 2.0-2.2: 高估
  - >2.2: 极度高估

#### 10. 美联储利率
- **数据来源**: 手动CSV导入
- **单位**: 百分比
- **影响**: 宏观流动性环境

#### 11. 日央行利率
- **数据来源**: 手动CSV导入
- **单位**: 百分比
- **影响**: 日元套利交易

#### 12. 个人评级
- **计算方式**: 8个指标评分总和
- **范围**: -16 到 +16
- **数据来源**: 自动计算

## 评分系统

### 🎯 评分机制

## 脚本使用指南

### 📜 核心脚本说明

#### 1. collectWeeklyDataV2.js
**用途**: 收集当前周和近期周的BTC/ETH价格数据（使用CoinGecko API）

**特点**:
- 自动重试机制（失败后重新收集）
- 只收集缺失的数据，不覆盖已有数据
- 适用于1年内的数据收集

**使用方法**:
```bash
cd 04-coin-index
node scripts/collectWeeklyDataV2.js
```

**输出**:
- 更新 `public/weeklyData.json`
- 更新 `src/data/weeklyData.json`

**注意事项**:
- ⚠️ 默认只更新没有数据的周
- ⚠️ 不会修改已有数据
- ⚠️ API限流：每次请求间隔25秒

#### 2. collect2025AllWeeks.js
**用途**: 收集2025年全年历史数据（使用Yahoo Finance API）

**特点**:
- 突破CoinGecko 1年限制
- 适用于历史数据补全
- 一次性收集整年数据

**使用方法**:
```bash
cd 04-coin-index
node scripts/collect2025AllWeeks.js
```

**使用场景**:
- 初次设置项目时收集历史数据
- 补全缺失的历史周数据

**注意事项**:
- ⚠️ 只用于1年以前的数据
- ⚠️ 不要用于当前周数据收集

#### 3. importManualData.js
**用途**: 从CSV文件导入手动数据并计算评分

**数据内容**:
- 恐惧&贪婪指数
- 梅耶倍数
- Ahr999指标
- BTC四年指数
- 美联储利率
- 日央行利率

**使用方法**:
```bash
# 1. 编辑 data-import.csv 文件
# 2. 运行导入脚本
cd 04-coin-index
node scripts/importManualData.js
```

**CSV格式**:
```csv
周ID,恐惧&贪婪指数,梅耶倍数,Ahr999指标,BTC四年指数,美联储利率,日央行利率
2026-W06,45,0.92,0.68,1.85,3.5,0.75
```

**注意事项**:
- ⚠️ 周ID格式必须是 `YYYY-WXX` (如 `2026-W06`)
- ⚠️ 利率数据可以带%符号或不带（脚本会自动处理）
- ⚠️ 导入后会自动计算个人评级

**统计数据**:
- 总交易次数
- 胜率
- 平均持仓周数
- 最大盈亏

#### 4. YearSummary.jsx
**功能**: 年终总结

**统计内容**:

- 连涨连跌统计
- 市场趋势统计
- 个人评级统计
- 模拟演练统计

## 每周数据更新流程

### 📅 标准更新流程（重要！）

**⚠️ 核心原则**:
1. **只更新没有数据的周**
2. **永远不修改已有数据**（除非人类明确要求）
3. **默认使用CoinGecko API**
4. **1年以前的数据使用Yahoo API**

### 🔄 每周更新步骤

#### 步骤1: 收集API数据
```bash
cd 04-coin-index
node scripts/collectWeeklyDataV2.js
```

**脚本行为**:
- 检查哪些周缺少数据
- 只收集缺失的周数据
- 不覆盖已有数据

#### 步骤2: 准备手动数据
编辑 `data-import.csv` 文件，添加新周的数据：

```csv
周ID,恐惧&贪婪指数,梅耶倍数,Ahr999指标,BTC四年指数,美联储利率,日央行利率
2026-W06,45,0.92,0.68,1.85,3.5%,0.75%
```

#### 步骤3: 导入手动数据
```bash
node scripts/importManualData.js
```

**脚本行为**:
- 读取CSV文件
- 合并到weeklyData.json
- 自动计算个人评级
- 同步更新两个JSON文件

#### 步骤4: 验证数据
```bash
# 检查最新周数据
node -e "const fs = require('fs'); const data = JSON.parse(fs.readFileSync('public/weeklyData.json', 'utf8')); const weeks = Object.keys(data).sort(); console.log('最新周:', weeks[weeks.length-1]); console.log('数据:', data[weeks[weeks.length-1]]);"
```

#### 步骤5: 测试前端
```bash
npm run dev
# 访问 http://localhost:5173
# 检查新周数据是否正确显示
```

### ⚠️ 重要警告

**禁止操作**:
- ❌ 不要修改已有周的数据（除非人类明确要求）
- ❌ 不要重新运行历史数据收集脚本
- ❌ 不要手动编辑weeklyData.json（使用脚本）

**允许操作**:
- ✅ 收集新周数据
- ✅ 补全缺失周数据
- ✅ 更新CSV后重新导入

## 故障排查

### 🔧 常见问题

#### Q1: 前端显示404错误
**症状**: 控制台显示 `GET /weeklyData.json 404`

**原因**: 数据文件路径问题

**解决方案**:
1. 检查 `public/weeklyData.json` 是否存在
2. 检查文件权限
3. 清除浏览器缓存（Ctrl+F5）

#### Q2: 红绿点不更新
**症状**: 修改数据后日历红绿点没变化

**原因**: 浏览器缓存或全局缓存未更新

**解决方案**:
1. 强制刷新浏览器（Ctrl+Shift+R）
2. 检查 `window.weeklyDataCache` 是否更新
3. 重启开发服务器

#### Q3: 个人评级计算错误
**症状**: 评分与预期不符

**原因**: 某个指标数据缺失或格式错误

**解决方案**:
1. 检查所有8个评分指标是否都有数据
2. 检查数据格式（利率是否为数字）
3. 重新运行 `importManualData.js`

#### Q4: API收集失败
**症状**: `collectWeeklyDataV2.js` 报错

**原因**: API限流或网络问题

**解决方案**:
1. 等待25秒后重试
2. 检查网络连接
3. 使用Yahoo API作为备选（历史数据）

#### Q5: CSV导入失败
**症状**: `importManualData.js` 报错

**原因**: CSV格式错误

**解决方案**:
1. 检查周ID格式（必须是 `YYYY-WXX`）
2. 检查是否有空行
3. 检查数据是否完整（6个指标）
4. 使用UTF-8编码保存CSV
